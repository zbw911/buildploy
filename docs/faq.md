# 常见问题

## 官网、工作台和这个仓库有什么区别？

- [官网](https://www.buildploy.com/)：介绍产品和提供入口。
- [工作台](https://code.buildploy.com/)：实际构建、预览和交付应用。
- [本仓库](https://github.com/zbw911/buildploy)：公开使用文档、问题反馈与功能建议。

## 为什么不能直接注册？如何申请开通？

由于资源有限，Buildploy 暂未开放公开注册，目前采用白名单机制。如需开通体验，请发送邮件至 [zbw911@qq.com](mailto:zbw911@qq.com)，或通过 [GitHub Issue](https://github.com/zbw911/buildploy/issues/new/choose) 联系作者。已开通用户可正常登录。

白名单内的新手机号验证通过后可完成注册。申请所需手机号请通过邮件沟通，不要公开填写在 Issue 中。

## 可以从这里下载平台源码或自部署吗？

本仓库是文档与反馈中心，不提供平台完整源码或自部署安装包。请使用在线工作台。

## 支持哪些应用目标？

Buildploy 围绕 Web、微信小程序、Android 和业务工作流提供构建与交付能力。具体项目能够使用的目标、运行环境和产物类型，以工作台实际提供的操作和结果为准。

## AI 已经回复完成，为什么应用仍然有问题？

会话中的轮次结束只说明本次处理结束。还需要检查工具执行结果，并实际运行应用、操作关键路径。反馈时请区分 AI 回复、构建报错和应用运行报错。

## 预览正常，是否代表已经发布？

预览用于验证运行效果。发布或打包需要查看相应交付记录，确认状态、产物和访问入口。不同目标端应分别验证。

## 反馈需要提供什么？

提供问题发生时间及其时区、浏览器或设备、目标端、复现步骤、预期与实际结果，以及脱敏后的报错或截图。可提供不含访问凭据的会话或轮次标识，帮助定位；不要提交私密项目地址或业务数据。详见[反馈指南](../CONTRIBUTING.md)。

## 文档缺失或不准确怎么办？

欢迎提交文档问题 Issue，或通过 Pull Request 修改文档。请说明所依据的实际页面与操作，不要将内部配置或未经确认的能力写成公开承诺。
